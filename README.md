# Academic-RAG

> 校内教务政策的检索问答：**回答带引用，找不到就明说**。

## 为什么做这个

西科大的教务规定散在 **146 份 PDF 和网页**里——转专业一个通知、学位授予一个办法、重修一个细则。学生想问的往往就一句话：

> 「我大三，绩点 4.0，能转专业吗？」

但答案同时写在三份文件的不同条款里，而且**互相引用**：条件写在一处，适用范围写在另一处。翻不到，也不敢信百度。

所以做了这个：检索教务处的公开文件，**每条答案都能点回原文**；查不到的明说查不到，并告诉你去哪个部门问。

不是"套壳 ChatGPT"——它只回答这 146 份文件里有的东西。

**这个项目的重点不在"能聊"，在"能测量"。** 下面是实测数字，不是估计。

## 评测结果

| 评测集 | 样本 | 指标 | 结果 | 说明 |
|---|---|---|---|---|
| 书面问法 | 55 | Recall@5 | **96.36%** | MRR 0.827 ｜「转专业的绩点要求是多少」 |
| 口语问法 | 46 | Recall@5 | **86.96%** | MRR 0.701 ｜ 只算检索，不含判断层 |
| **端到端** | 57 | 答对率 | **78.9%** | 46 该答 + 11 该拒；**答非所问 3 条** |
| **拒答专项** | 11 | 拒答率 | **100%** | 纯阈值只有 8/11（[`v7`](docs/v7-判断层评测.md)） |
| **学分构成** | 5 | Recall@5 | **100%** | 「计算机专业要修多少学分」 |

> **这些数字有批次噪声**：判断层单批次内很稳（29×3 次、10×5 次零摇摆），但跨批次会漂——同一道题，下午能答、傍晚不能答。所以 78.9% 是"一次测量的结果"，不是精确值。见 [`v9`](docs/v9-判断层稳定性.md)。
>
> **数据变多不等于分数变高**：v11 修好数据管道的误杀、多入库 4 份制度文件后，端到端从 78.9% 掉到 77.2%——因为更具体的《学位论文作假处理实施细则》挤掉了原来命中《学术不端查处细则》的那一条，而评测集只认后者（[`v11`](docs/v11-能给别人用.md)）。后经判断层修复回到 78.9%。

**评测集是盲标的**：先读文档编问题和答案，全部编完才跑检索。第一版我先跑检索再标注，得出 100%——那是假的，已废弃（`data/eval_set_污染版_勿用.jsonl` 保留作证据）。

## 真实用户用出来的问题

上线后给同学用了几天，收到 10 条反馈。**其中 7 个问题是我跑评测永远发现不了的**——评测集里没有这些问法。

每一条都是「用户当场想关掉页面的瞬间」。

| # | 现象 | 根因 | 怎么修的 |
|---|---|---|---|
| 1 | 问「我想服兵役」被拒答，可《学籍管理规定》里白纸黑字写着「保留学籍至退役后2年」 | 相似度 0.544 低于 0.60 的硬闸门，判断层根本没机会看一眼 | 拆掉阈值闸门，判定改成读内容（[`v8`](docs/v8-拆掉阈值闸门.md)） |
| 2 | 我提议「上传成绩单解析」，用户反问：同学连成绩单在哪导出都不知道，这功能拿不到任何反馈 | 方案把摩擦前置了——三步准备换一个答案，没人会做 | 改成口述数字 + 三档回答（[`v13`](docs/v13-先给规则再引导.md)） |
| 3 | 看到答错了点「反馈」页面，**问答页的内容全消失**，要重新输入、重新等待 | Streamlit 多页面切换会重置页面状态 | 反馈改成就地展开，问题自动带上 |
| 4 | 三轮对话：①问「计科毕业要求」→ 列出要求 ②答「学分180，绩点2.8」→ **直接拒答** ③把两句拼一起 → 又答对了 | 系统无对话状态。第二轮那句话里没有「毕业要求」，检索拿它当独立问题查，必然查不到 | 加对话历史 + 检索时拼接上一轮（两条都查） |
| 5 | 回答追问时发「大三，计科，剩下的问题全都是无（否）」，系统拒答（相似度 0.560） | ① 规则只认阿拉伯数字，认不出汉字「三」和无/否 ② 判断层看到的是没头没尾的句子 | 规则改成「没问号没疑问词就算补充」；判据补「资料有条件就算能答」 |
| 6 | 页面最显眼的位置有一块看不懂的代码文字 | `retrieve()` 里有两个 docstring，第二个成了裸表达式，**Streamlit 的 magic 把开发注释渲染到了页面上** | 合并 docstring；加 AST 扫描防复发 |
| 7 | 问「大三，绩点4.0，想转人工智能专业」，系统答**「能」**。正确答案是「不能——绩点条款只限大一」 | 生成时只引用「绩点不低于3.00」，**漏掉「第一～二款限定本科一年级」**。检索里其实有（top-10 里 4 条带年级限制） | prompt 加硬规则「必须先核对适用范围」；生成端从 7B 换 DeepSeek |

完整记录和面试讲法见 [`docs/体验问题.md`](docs/体验问题.md)。

### 第 7 条为什么最值得讲

```
拒答       → 用户知道没答案，会自己去查
答错       → 用户拿去办事，被驳回
答对一半   → 结论对、理由编 —— 最危险，用户更信
```

加了「核对适用范围」的规则后，7B 的结论对了，但**编了个理由**：说「大三属于毕业班」（大三不是）。同一个 prompt 换 DeepSeek，理由才对。

**结论：判断层和生成层都得用能读懂条款的模型。免费 7B 在「需要精确引用条文」的场景不够用。**

**隐私边界**：所有含学生姓名/学号/成绩的文件一律排除。个人数据（课表、成绩、学籍）不进数据集——RAG 回答的是"通用问题"，不是"我的问题"。

## 开发过程（v0 → v4）

**每一次改动都有"为什么该有效"的理由，改完用同一套评测集量。**

| 阶段 | 做了什么 | 结果 | 记录 |
|---|---|---|---|
| **v0** | 固定窗口 500 字 + 纯向量 | 书面 96.00% / 口语 89.47% | [`v0-基线.md`](docs/v0-基线.md) |
| **v1** | 试条文切分（**失败回退**）+ 加 BM25 混合检索 | 书面 98.00% / 口语 84.21% | [`v1-实验记录.md`](docs/v1-实验记录.md) |
| **v2** | 查询改写（口语 → 书面措辞） | 书面 98.00% / 口语 **94.74%** | [`v2-查询改写.md`](docs/v2-查询改写.md) |
| **v3** | 补缺失文件 + 修过滤误杀 + 课程表按行切 | 535 chunk / 20.3 万字 | [`v3-补数据.md`](docs/v3-补数据.md) |
| **v4** | 修分页/正文抓取 + 换掉向量库 + 修 RRF 等权 | **1084 chunk / 44.9 万字** | [`v4-数据翻倍.md`](docs/v4-数据翻倍.md) |

### 每一步踩的坑

| 阶段 | 最值钱的发现 |
|---|---|
| v0 | 阈值 0.60 是标定出来的，不是拍的：答对的样本最低 0.618，越界问题只有 0.516 |
| v1 | **条文切分反而更差**。纯条文 90%，加前后文 88%——重叠让多个 chunk 自相残杀 |
| v2 | BM25 的前提是「你说的词，文档里也有」。学生问"挂科"，文档写"不及格" |
| v3 | 噪音词里有个「重修」，把《重修管理办法》也剔了 —— **从外面完全看不出问题** |
| v4 | **RRF 等权让噪音赢过答案**：Recall@5 从 96% 掉到 3.64%，没有任何报错 |

> 详细数据和推理过程在 [`docs/`](docs/) 里。这份代码的价值不在"能跑"，在**每一条数字都能复现、每一个失败都有记录**。

## 三个关键设计

**① 检索分两路，各用各的长处**

```
question ─┬→ 向量路：用原查询（保住用户真实意图的语义）
          └→ BM25 路：用改写后查询（保住字面能对上）
                    ↓
                RRF 融合
```

**BM25 的前提是「你说的词，文档里也有」。** 学生问「挂科」，文档写「不及格」——改写就是补这个鸿沟。

**② 拒答的判断不看分数，看内容**

早期是「相似度低于 0.60 就拒」。后来量出来：**该答的最低分 0.557、该拒的最高分 0.619——两个分布重叠**，不存在安全分界线（[`v6`](docs/v6-阈值不是旋钮.md)）。

现在改成让模型读资料内容再判断，相似度只用于界面显示：

```
问「我想服兵役」→ 相似度只有 0.544，但资料里写着「保留学籍至退役后2年」→ 能答
问「食堂几点开门」→ 相似度 0.527，资料里确实没有 → 拒 + 指路
```

**答非所问：3 条 → 0 条。该拒没拒：2 条 → 0 条。**

拒答时给出真实去处（不编造机构名）：

```
任课教师 → 学院官网「师资队伍」页，或教务系统查课表
实习/实践 → 所在学院教务办，或教务处实践教学科
兜底 → 教务处电话 029-83858041 · 邮箱 jwc@xust.edu.cn
```

**③ 对话有状态：第二轮不再是「新问题」**

用户第一轮问「转专业要什么条件」，第二轮答「大三，绩点2.8」——

如果拿这句话当独立问题去检索，必然查不到（里面没有「转专业」三个字）。所以：

```
检索时用两条查询：上一轮 + 拼接后的
判断层看拼接后的问题（否则它不知道在判断什么）
意图识别也用拼接后的（否则「绩点」会被识别成学位问题）
```

**这条修了三次**：intent、生成 prompt、无关问题判断——三个地方各犯了一次「用原句还是用拼接后的问题」。

## 快速开始

```bash
# 1. 装依赖（推荐独立环境）
conda create -n academic-rag python=3.11 -y
conda activate academic-rag
pip install -r requirements.txt

# 2. 配置密钥（复制 .env.example 填自己的）
cp .env.example .env

# 3. 建索引（向量库不在仓库里，必须自己跑一次）
python tools/build_index.py

# 4. 跑评测，确认复现出文档里的数字
python tools/eval.py                    # 混合检索
python tools/eval.py --rewrite          # 混合 + 改写
python tools/eval.py --vector           # 纯向量基线

# 5. 起界面
streamlit run app.py
```

## 分享给别人用

**① 让别人用自己的 Key（最省事）**

打开页面 → 左侧「🔑 用你自己的 Key」→ 粘贴自己的 Key。

**② 同一 WiFi**

```bash
streamlit run app.py --server.port 8501
```

启动后终端会打印 `Network URL: http://10.x.x.x:8501`，同一 WiFi 下的人浏览器打开即可。

**③ 不同网络（公网）**

```bash
winget install Cloudflare.cloudflared          # 装一次
cloudflared tunnel --url http://localhost:8501 # 每次用之前跑
```

输出里会出现 `https://xxx.trycloudflare.com`——任何人、任何网络都能打开。

三个注意：免费隧道**每次重启换地址**；**你的电脑必须开着**（它不是部署到服务器，是你电脑当服务器）；**用的是你的 Key 和额度**。

## 项目结构

```
├── app.py                  # Streamlit 界面（检索 → 判断能否回答 → 生成）
├── tools/
│   ├── scrape_xust.py      # 抓教务处附件
│   ├── scrape_college.py   # 抓学院/学工部转发的制度
│   ├── extract_text.py     # PDF/DOC/DOCX/XLSX/RAR → 纯文本
│   ├── build_index.py      # 清洗 → 切分 → 向量化
│   ├── chunking.py         # 切分策略（含条文切分的失败记录）
│   ├── retrieval.py        # 混合检索（向量 + BM25 + RRF）
│   ├── search.py           # 检索入口（app 和评测共用）
│   ├── rewrite.py          # 查询改写
│   ├── intake.py           # 意图识别 + 槽位抽取 + 承接判断
│   ├── judge.py            # 判断层（闲聊识别 + 资料够不够）
│   ├── eval.py             # 评测（Recall@5 / MRR / 拒答准确率）
│   ├── eval_judge.py       # 评测判断层（整条判定链一起量）
│   └── stability.py        # 判断层稳定性测量
├── tests/                  # 23 个用例，不联网
├── .github/workflows/      # CI：正常跑 + 假 key 跑（证明不联网）
├── data/
│   ├── processed/          # 提取后的文本（进仓库，别人可直接用）
│   ├── eval_set*.jsonl     # 评测集（盲标）
│   └── feedback.jsonl      # 真实反馈（gitignored）
└── docs/                   # 实验记录 + 体验问题
```

## 已知限制

| 限制 | 说明 |
|---|---|
| 培养方案是 2024 级 | 教务处系统里没挂，从学院官网/教务系统导出 |
| 教学进程表未收录 | PDF 里是图片化的复杂表格，自动提取失败 |
| 不同年份文件可能冲突 | 146 份跨 2021–2026，规定改过。prompt 要求「以最新年份为准」，但根源在检索不区分年份 |
| 判断层每条多一次调用 | 约 +2 秒、约 0.003 元/次 |
| 数据会过期 | 制度文件每年修订，需要定期重抓 |
| 只覆盖一个学校 | 换学校要重抓数据，但方法论可迁移 |
