# v5：向量路的回退（2026-11-06）

> 这一轮没有加功能，是**把一个已经合并的改动撤回来**。
> 最值钱的部分不在代码里，在于发现「我手里两把尺子量出来不一样」。

## 结论

PR #1 让向量路也用改写后的查询。回退，恢复成原查询。

| 模式 | Recall@5 | MRR | 误拒率 | 用户真正拿到答案 |
|---|---|---|---|---|
| `orig`（回退后，当前默认） | **86.21%**（25/29） | 0.702 | 10.34%（3/29） | 23/29 |
| `rewrite`（PR #1 的改法） | 79.31%（23/29） | **0.724** | **0%**（0/29） | 23/29 |

**两个指标方向相反。** 按「用户能不能拿到答案」算，两边打平。

选 `orig` 的理由：

- 误拒是**阈值标定问题**——3 条里 2 条召回命中了（保研 0.557、重修交钱 0.573），只是低于 0.60。改阈值能修。
- 召回失败是**检索能力问题**——翘课、延毕两条，文档里根本没有学生用的那个词。改阈值修不了。

**能修的交给阈值，修不了的才是检索该背的账。**

## 为什么会有这个 PR

问「保研要求」，系统答不出来。查了才发现：

```
文档里「保研」出现 0 次
      「推免」只有 2 次
```

v2 的查询改写本来能处理这种情况——它把「保研要求」翻成「推荐免试研究生 条件 申请要求 资格 选拔办法」。

**但改写结果只给了 BM25 路用，向量路还在用原词「保研」。**

单条验证看着极好：

```
orig     0.562  形势与政策（无关）
rewrite  0.770  推免方案 ✅
```

于是判断「向量路也该用改写」，建 PR #1，合并。

## 怎么发现错的

合并后补了 5 条「口语缩写」评测题（保研 / 挂科 / 绩点 / 翘课 / 延毕），口语集从 24 条变成 29 条，跑完整评测：

```
orig     25/29 = 86.21%
rewrite  23/29 = 79.31%
```

**单条更好，整体更差。**

具体掉在哪：`转专业要多少绩点啊` 从 rank 5 掉出前 5；`开学多久内要办学分认定` 从 rank 4 掉出。而改写让 `毕业证找不着了咋办` 的相似度从 0.650 涨到 0.705——涨的是分数，不是命中。

## 踩的坑：两把尺子

先用临时脚本 `quick_eval.py` 测，得到 83% vs 79%。
再用正规脚本 `eval.py` 测 orig，得到 **86.21%**（25/29）——**数字对不上**。

`eval.py` 当时根本不支持 `vec_mode`，`do_search()` 里写死了默认值：

```python
res, sim = retriever.search(q, k=K, rewrite=use_rewrite)   # 没有 vec_mode
```

也就是说：**它测的永远是 `orig`，而我以为它能测两种模式。**

处理：给 `eval.py` 加 `--vec-mode=orig|rewrite|both`（默认 orig），两个模式**用同一个装置**重测，上表那两组数字就是这么来的。

`quick_eval.py` 降级为冒烟测试（只看「修复有没有效」），**正式数字只认 `eval.py`**。
它和 `eval.py` 至今仍差 1 条（`转专业要多少绩点啊`），原因未查明——这条差异留在账上，不装作不存在。

## 这个 PR 该不该合

**该合。** 但不是因为它「有效」，而是因为：

- 它证明单条 case 的改善**不能**推断批量指标；
- 它逼出了「误拒率」这个以前没量过的指标；
- 回退本身是记录——比一条「优化了」的假提交值钱。

## 遗留

| 项 | 说明 |
|---|---|
| 误拒 3 条 | 阈值 0.60 是按 `orig` 的分布标的，改写后分布整体右移。按模式分别标定 |
| 翘课 / 延毕 | 文档里写「旷课」「延长学习年限」，学生不说这两个词。要继续扩同义词表 |
| `quick_eval` 差 1 条 | 未查明，正式评测不用它 |
