# v4：数据翻倍（2026-11-05 凌晨）

> 这一轮改的是**数据层**，不是算法。但踩到的坑比前三轮加起来多。

## 一句话总结

**从 73 份文件 / 535 chunk → 141 份 / 1084 chunk**，同时修了四个会静默毁掉结果的 bug。

---

## 四个 bug（都是"结果错了但没人报错"那种）

### ① 分页只抓了第一页 —— 漏掉 86% 的文章

「学籍与学位」栏目页面底部写着：

```
共288条  1/8
```

**我们只抓了第 1 页的 40 篇。** 推免方案就在后面的页里——所以问"保研要求"永远答不出来，而且从外面看不出问题。

博达 CMS 的分页参数是 `a196064p={页码}`（前缀随栏目变化），不是我一开始试的 `page=2`。

**修法**：从第一页 HTML 里挖出分页链接模板，只替换 `p=` 后面的数字。

### ② 只抓附件，漏了「正文即全文」的文章

抓取逻辑是"进文章页 → 找 `download.jsp` 附件 → 下载"。

但**推免方案这类文章没有附件，正文直接写在网页上**。结果：

```
推免方案（6092）→ 文章页有 7391 字正文 → 但没附件 → 被跳过
```

**修法**：另写 `scrape_college.py` 抓网页正文（先把正文容器里的文字抽出来）。

### ③ Chroma 在 1070 条时崩溃

```
InternalError: Error loading hnsw index
```

535 条时好好的，1070 条就坏。分批写入、删库重建都修不好。

**换成 numpy 手算**：1084 条 × 1024 维，点积一次约 1ms。

> **工具要匹配规模。** 1000 条的数据不需要向量数据库，而且那个数据库在这个量级还会坏。

### ④ RRF 等权让噪音赢过答案

这是**最隐蔽**的一个。纯向量检索明明是对的：

```
平均绩点多少才能拿到学士学位
  0.746  学士学位授予工作实施办法   ← rank 1，完全正确
```

但 RRF 融合后，这条**掉出了 top-5**。原因：

```
正确答案：向量 rank=1            → RRF = 1/61 = 0.0164
无关文件：向量 rank=2 + BM25 rank=1 → RRF = 1/62 + 1/61 = 0.0325  ← 翻倍
```

**RRF 奖励的是「数量」不是「质量」。** 一个被切成 20 个 chunk 的无关文件，只要在 BM25 路召回 10 个，就能把这 10 个全顶到前面。

**Recall@5 从 96% 掉到 3.64%** —— 而且没有任何报错。

**修法两步**：
1. 给向量路更高权重（`VEC_W=1.0, BM25_W=0.4`）
2. **按文件去重**：每个来源文件最多留 2 个 chunk

修完前 10 条从 3.64% 回到 **90%**。
