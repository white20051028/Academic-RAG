# v12：复合问题拆分检索——三次改法，两次更差

> 目标：从「一次检索」变成「按子问题检索几次」。
> 这是从 RAG 走向 Agent 的第一步——让系统自己决定查几次。

## 一、先出题，第一次就翻车

造了 10 道复合题（「辅修能抵学分吗，最多抵多少」这类），跑改前基线：

```
10/10 = 100%
```

**单次检索全对。** 原因：我把两个子答案都出在了**同一份文件**里，top-5 本来就装得下两份 chunk。

那不是复合问题，是"一句话问了两件事但答案挨着"。

补了 5 道**跨文件**的（一个答案在 A 文件、一个在 B 文件），基线才掉到：

```
13/15 = 86.7%
```

## 二、三版对比

| 版本 | 完整答对 | 子答案命中 | 至少答一半 |
|---|---|---|---|
| 不拆（k=5） | 13/15 = 86.7% | 27/30 = 90% | 93.3% |
| 拆成关键词串（k=5） | 9/15 = **60%** | 22/30 = 73.3% | 86.7% |
| 拆成完整问句（k=5） | 12/15 = 80% | 26/30 = 86.7% | 93.3% |
| **拆成完整问句（k=8）** | **13/15 = 86.7%** | **28/30 = 93.3%** | **100%** |

## 三、两个结论

### ① 不能拆成关键词串

第一版让模型输出「辅修 抵 主修 学分」「辅修 学分 上限 认定」这种裸词。

**从 86.7% 掉到 60%。**

原因和 v5「改写抹平语序」是同一类错误：**向量检索靠的是整句的语义**，抽成裸词之后每个词权重被放大，匹配反而更差。

改成完整问句（「辅修能抵主修学分吗」「辅修最多能抵多少学分」）就回到 80%。

### ② 拆了必须放大检索宽度

完整问句 + k 不变（5 条）：2 个子查询各分 2-3 条，**比不拆还少**，所以 80% < 86.7%。

把宽度翻倍（k=8）：子答案命中 90% → 93.3%，「至少答出一半」93.3% → **100%**。

**拆分的收益不在"检索更准"，在"覆盖更全"。**

## 四、所以实现是这样的

```python
# app.py retrieve()
subs = planner.split(query, ...) if planner.is_compound(query) else [query]
width = min(k * 2, 10) if len(subs) > 1 else k
```

- **先规则后模型**：57 条评测集里只有约 1/4 是复合的。不筛的话，75% 的查询白等 2 秒。
- **宽度上限 10**：再大就会塞太多无关内容给生成模型。

## 五、代价

**复合问题多一次模型调用（约 2 秒）+ 检索宽度翻倍。**

非复合问题完全不受影响。

## 六、诚实评估

**收益很小：完整答对没提升（86.7% = 86.7%），只有子答案命中 +3.3 点。**

严格说，这个改动**没有证明自己值得**。真正的价值在两个副产品：

1. **「至少答出一半」从 93.3% → 100%**——用户不会再拿到半个答案，这是体验上的明确改进。
2. **planner 是 Agent 的地基**。要做 B 方案（工具调用），第一步就是"让模型决定下一步做什么"，这个模块正好复用。

如果只看数字，这一轮可以不做。但它是 B 的前置。

## 遗留

| 项 | 说明 |
|---|---|
| 完整答对没提升 | 15 道题里 2 道始终答不全（微专业没修完、退伍复学学分），是检索本身的短板，拆不拆都一样 |
| 只有 15 道复合题 | 样本太小，±1 条就是 6.7 个百分点。要更可信得 40 道以上 |
| 出题人是我自己 | 第一版就翻车了（全对）。真盲标得让别人出题 |
| B 方案未开始 | 工具调用（`search_policy` / `get_credit_rule`），模型自己选工具 |
