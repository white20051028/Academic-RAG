# v6：阈值不是旋钮，是跷跷板（2026-11-06）

> 这一轮没改一行线上代码。
> 它只回答一个问题：**「把拒答阈值从 0.60 降到 0.55，是不是就能救回那 3 条误拒？」**
> 答案是不能，而且原因比"调一下就行"难看得多。

## 一句话结论

**0.60 已经是这条曲线上最优点。** 往左走救误拒，代价是放大误答；往右走压误答，代价是误拒暴涨。
而且真正的问题不在阈值——**「该答的」和「该拒的」在相似度上是重叠的，没有一条线能分开。**

## 这个实验是怎么被逼出来的

v5 回退之后，我说了一句「误拒是阈值标定问题，改阈值能修」。

用户当场反驳：

> 「你降低阈值本身就是提高了 RAG 去强行回答自己回答不了问题的风险，这只能说是做了取舍，而不是完美的解决了误拒。」

**他是对的。** 于是把这个"取舍"量出来。

## 方法：为什么只需要跑一次检索

阈值只影响「拒不拒」这个判断，**不影响检索本身**。
同一个问题，检索出来的 `best_sim` 是固定的，阈值只是拿它跟一个数比大小。

所以：**每个评测题只跑一次检索，拿到相似度，然后本地扫所有阈值。**
不用为每个阈值重跑一遍 API（那要 10 倍时间，且结果完全相同）。

## 数据

两组：**10 条该拒的**（师资、食堂、图书馆、考研等）+ **29 条该答的**（口语集）。

### 该拒的 10 条，各自的相似度

```
0.5522  高等数学老师都有谁
0.6072  计算机学院有哪些老师        ← 超过 0.60，被答了
0.5994  大三学生想出去实习可以请假吗
0.5270  食堂几点开门
0.5936  宿舍怎么申请
0.5504  学校有几个校区
0.5396  图书馆开放时间
0.5731  怎么申请国家奖学金
0.6190  考研需要什么条件            ← 超过 0.60，被答了
0.5403  我们学校全国排名多少
```

### 扫描结果

| 阈值 | 该拒被拒（10） | 该答被误拒（29） | 合计错 |
|---|---|---|---|
| 0.63 | 10 = 100% | 7 = 24.1% | 7 |
| 0.62 | 10 = 100% | 6 = 20.7% | 6 |
| 0.61 | 9 = 90% | 4 = 13.8% | 5 |
| **0.60** | **8 = 80%** | **3 = 10.3%** | **5** ← 最优 |
| 0.59 | 6 = 60% | 3 = 10.3% | 7 |
| 0.58 | 6 = 60% | 3 = 10.3% | 7 |
| 0.57 | 5 = 50% | 1 = 3.4% | 6 |
| 0.55 | 3 = 30% | 0 = 0.0% | 7 |
| 0.53 | 1 = 10% | 0 = 0.0% | 9 |

**0.60 和 0.61 并列最优（各错 5 条）。** 这是一条 U 形曲线，不是单调的。

## 为什么再调也没用

```
该答的最低分   0.5570   保研要求是什么
该拒的最高分   0.6190   考研需要什么条件
```

**正确的答案，分数比垃圾还低。**

这不是"阈值没选好"，是**两个分布重叠**。在重叠区里，任何阈值都必然同时犯两种错之一：

- 卡在 0.557 以上 → 保研被误拒
- 卡在 0.619 以下 → 考研被乱答

**相似度这个维度上，根本不存在一条能分开两者的线。**

## 这说明什么

相似度只能回答「**这段文字和你的问题像不像**」。

它回答不了「**这些材料够不够回答你的问题**」。

- 「保研要求是什么」和「推免方案」——很像，但文档里写的是研究生推免，不是本科生保研流程。**像，但不够。**
- 「考研需要什么条件」和「研究生招生简章」——也很像。**像，但不是这个学校本科生该看的。**

这两种"像"在数值上没有区别。**要区分它们，必须看内容，不能看分数。**

## 所以下一步不是调参，是加一层判断

```
检索（现有）→ 粗筛（阈值 0.50，只拦明显无关的）→ 判断层（新）→ 答 / 拒
                                                      ↑
                                    拿前 5 条的内容问："这些材料能回答这个问题吗？"
```

- 阈值降到 0.50 只做**粗筛**——它现在唯一的用途是"省一次模型调用"，不再是判断依据。
- 判断层看的不是分数，是**文本**：答案里有没有覆盖问题的每一个要件。

**这一步还没做，也还没量。** 写在这里是因为：如果先做判断层再定这个结论，就成了「先有答案再找证据」。

## 遗留

| 项 | 说明 |
|---|---|
| 判断层 | 未实现。设计要考虑成本（每条问题多一次调用）和延迟 |
| 判断层的评测集 | 现有的拒答集只有 10 条，做判断层至少要扩到 30 条，且要包含"像但不够"这类 |
| 0.61 vs 0.60 | 合计错一样，但 0.61 拒得更准、误拒更多。选 0.60 是因为误拒对用户更烦 |
| 单条相似度的稳定性 | 同一问题两次调 API 的 embedding 可能微抖，边界样本（0.5994 / 0.6072）可能翻转 |
