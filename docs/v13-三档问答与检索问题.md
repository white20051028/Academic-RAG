# v13：三档问答跑通了，但它暴露了三个检索问题

> 这一轮的目标是「先给规则，再引导补信息」（见 `产品判断-先给规则再引导.md`）。
> 功能做出来了，但真正值钱的是**它把检索的底子照出来了**。

## 一、做了什么

| 输入 | 行为 |
|---|---|
| 「我大二，绩点2.8，能转专业吗」 | 对照条件直接判断 |
| 「我大二，能转专业吗」 | 列完整要求 + 指出缺绩点 + 引导 |
| 「转专业有啥要求」 | 列完整要求 + 结尾引导补信息 |

实现：`tools/intake.py` 做意图识别 + 槽位抽取（正则，不调模型），`app.py` 按信息完整度选 prompt。

**抽取准确率 10/10**（测试了 10 种说法）。

## 二、跑通之后，第二档给出了错答案

```
问题：我大二，绩点2.8，能转专业吗
模型：资料里没有明确规定绩点的具体要求，建议咨询教务处
```

**但资料里有。** 《2026 年度本科生转专业工作的通知》里写着：

> 入学一学年平均学分绩点（不含公共选修课）不低于 **3.00**

于是顺着查下去，发现三个问题。

## 三、问题一：用户提供的个人信息污染了检索

同一件事，三种问法：

| 查询 | 相似度 | 能召回「3.00」那条吗 |
|---|---|---|
| 我大二，绩点2.8，能转专业吗 | 0.673 | ❌ |
| 能转专业吗 | 0.713 | ❌ |
| 转专业 绩点要求 | 0.746 | ✅ |

**「大二」「2.8」这些数字抢走了「转专业」的语义权重。** bge-m3 对整句做 embedding，个人信息越多，主题越淡。

这是三档设计的直接后果：**我们鼓励用户补充信息，补充的信息反而让检索变差。**

## 四、问题二：检索对措辞极其敏感

同一个意图，只换措辞：

| 查询 | 能召回「3.00」吗 |
|---|---|
| 转专业 绩点要求 | ✅ |
| 转专业 申请条件 | ❌ |
| 转专业 要求 条件 流程 | ❌ |

**同一件事，命中与否取决于用了哪个词。**

我试过用「意图模板」统一查询（`转专业 绩点要求`），它能中；但换个模板就不中。
**靠精心调措辞去骗检索，不是工程解法**——它今天能中，明天数据一变就不中了。

## 五、问题三：同主题的多个年份版本互相稀释

查「我大二，绩点2.8，能转专业吗」时，top-5 是：

```
2026 版转专业通知   ← 一条
2025 版转专业通知   ← 一条
2023 版转专业通知   ← 一条
2021 版转专业通知   ← 一条
学生管理规定        ← 一条
```

四份内容几乎一样的通知，各占一格，把真正含「3.00」的那段挤了出去。

**修法**（已做）：同主题旧年份降权 0.5，不删除。
修后 2026 版从占 1 格变成占 2 格——但含「3.00」那段仍没进来，被 `MAX_PER_FILE=2` 挡住了。

## 六、所以真正该修的是检索，不是 Agent

这一轮最大的收获是这个判断：

> **三档问答的前提是「检索能找到规则」。而这个前提现在不成立。**
> 在检索不稳的时候加 Agent，等于在一个会漏的桶上装水龙头。

三个问题的优先级：

| 问题 | 影响 | 修法 |
|---|---|---|
| 个人信息污染查询 | 所有带信息的追问都受影响 | 检索时剥离个人信息，用「主题 + 缺的槽位」重新构造查询 |
| 措辞敏感 | 无法根治 | 多查询融合（原话 + 2~3 个改写，合并 top-k） |
| 年份稀释 | 所有有多版本的文件 | 已做降权，还需要调 `MAX_PER_FILE` 或在切分时合并版本 |

## 遗留

| 项 | 说明 |
|---|---|
| 个人信息剥离检索 | 没做。现在直接用原话检索 |
| 多查询融合 | 没做。v12 的 planner 只处理「复合问题」，没处理「措辞敏感」 |
| `MAX_PER_FILE` | 还是 2。试过 3，含「3.00」那段仍不进来，说明问题在排序不在上限 |
| 三档只测了 4 个问题 | 没有批量评测。要给 15 道复合题那种规模才可信 |
| 「资料里没有」是错的 | 模型说资料没有时，可能只是检索没找到。**这是一个新的幻觉来源**——不是模型编，是它被喂了不完整的资料还以为完整 |
