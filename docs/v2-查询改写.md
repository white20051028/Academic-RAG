# v2：查询改写（2026-11-03 晚）

## 解决什么问题

v1 的 BM25 让书面评测 +2 点，但**口语评测掉了 5.3 点**。

原因：**BM25 的前提是「你说的词，文档里也有」。**

```
学生问：挂科了要重修吗
文档写：不及格学分、补考、重修
        ↑ 一个词都对不上
```

## 做法

**让模型把口语问题改写成"学校文件里会用的书面说法"**，但只用在 BM25 路：

```
              ┌→ 向量路：用原查询（保住用户真实意图的语义）
question ─────┤
              └→ BM25 路：用改写后查询（保住字面能对上）
                        ↓
                     RRF 融合
```

**为什么两路用不同的查询**：强行统一成一种写法，就会牺牲另一路的长处。各用各的才是混合检索的正确用法。

改写效果（实测）：

| 原问题 | 改写后 |
|---|---|
| 挂科了要重修吗 | 不及格 重修 补考 学分 课程考核 |
| 毕业证找不着了咋办 | 毕业证书 学位证书 补办 遗失 |
| 我绩点2.5能不能毕业 | 毕业 学位授予 平均学分绩点 2.30 条件 |
| 咋转专业 | 转专业 申请条件 办理流程 时间 绩点 |
| 家里有事能请多久假 | 请假 事假 期限 手续 审批 |

## 结果

| 评测集 | v0 纯向量 | v1 混合 | **v2 混合+改写** |
|---|---|---|---|
| 书面 50 | 96.00% / 0.820 | **98.00% / 0.890** | 98.00% / 0.857 |
| **口语 19** | 89.47% / 0.816 | 84.21% / 0.803 | **94.74% / 0.809** |
| 拒答 10 | 80% | 80% | 80% |

**净收益**：
- 口语 **+10.5 个点**（84.21% → 94.74%）
- 书面 Recall 不变，MRR 从 0.890 降到 0.857（**代价 0.033**）
- 拒答不变（因为阈值用向量相似度，改写只影响 BM25 路——**设计上就不该影响**）

**结论：默认开启改写。**

## 改写的边界：它救不了缺失的数据

改写能解决"措辞不匹配"，但解决不了"文档里根本没有"。

实测「挂科了要重修吗」：

```
改写后：不及格 重修 补考 学分 课程考核
检索结果：0.635 → 辅修专业管理办法
```

**仍然失败**，因为《本科生课程重修管理办法》这份文件**压根没抓**（v1 的引用空洞分析里列出来了）。

> **改写解决"怎么说"，补数据解决"有没有"。这两件事不能互相替代。**

## 性能

| 步骤 | 耗时 |
|---|---|
| 构建检索器（415 chunk + jieba 分词 + BM25） | 1.5 秒 |
| 检索一次（不改写） | 0.40 秒 |
| 检索一次（带改写，多一次 LLM 调用） | 0.91 秒 |

界面上感觉不到差别（用户点「生成回答」本来就要等 2–3 秒）。

## 改了什么代码

| 文件 | 改动 |
|---|---|
| `tools/rewrite.py` | **新增**。改写提示词 + few-shot（校园场景的口语→书面映射） |
| `tools/retrieval.py` | `search()` 加 `rewrite` 参数：向量路用原查询，BM25 路用改写后查询 |
| `tools/eval.py` | 加 `--rewrite` 开关；改了输出文件的 tag 区分三版结果 |
| `app.py` | `retrieve()` 换成 `HybridRetriever`，默认开启改写 |
